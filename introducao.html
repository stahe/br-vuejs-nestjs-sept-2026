    Este documento é uma continuação do curso “Um exemplo cliente/servidor - AngularJS 1.x / Spring 4,” escrito em 2014. Esse documento original construía uma pequena aplicação de agendamento de consultas médicas (“[RdvMedecins]”) com um servidor Spring 4 / Spring Data / Spring MVC e um cliente AngularJS 1.x .

    Doze anos depois, os dois frameworks utilizados evoluíram de forma significativa — ou até foram substituídos no uso corrente:

    • no lado do servidor, [NestJS] consolidou-se como um dos frameworks Node.js/TypeScript mais utilizados para construir aplicações web estruturadas, com uma filosofia semelhante à do Spring (módulos, controllers, serviços, injeção de dependência), mas dentro do ecossistema JavaScript/TypeScript;
    • no lado do cliente, o AngularJS 1.x foi completamente reescrito a partir de 2016 com o nome [Angular] (2, 4, 5… até a versão 22) - a abordagem adotada pela variante [Angular] / [NestJS] deste curso. Este documento adota uma abordagem diferente: [Vue.js] (criado por Evan You em 2014, após uma experiência no Google com o AngularJS), um framework “progressivo” : um núcleo focado na camada de view, complementado por um formato próprio de componente — os arquivos .vue (veja o Capítulo 4).

    O objetivo deste documento é retomar o estudo de caso original — a mesma aplicação, as mesmas funcionalidades, o mesmo banco de dados — e reconstruí-lo com as ferramentas atuais, mantendo o máximo possível a mesma progressão didática do documento de 2014.

    1.1. Uma reconstrução passo a passo

    O documento original tinha cerca de 300 páginas e abordava, além das funcionalidades centrais da aplicação — autenticação baseada em papéis (Spring Security) —, doze exemplos progressivos para aprender AngularJS 1.x passo a passo. Reconstruir todo esse conteúdo de uma só vez seria demorado e difícil de assimilar.

    Este documento cobre, portanto, as duas primeiras etapas da reconstrução:

    • a arquitetura geral da aplicação (inalterada em seu princípio);
    • o banco de dados (inalterado, exceto pela adição da tabela [users]);
    • o servidor [NestJS] completo, com todas as funcionalidades de consulta e de agendamento/cancelamento de consultas;
    • a autenticação baseada em token (JWT) e o controle de acesso por papéis (ADMIN/USER), equivalente à camada Spring Security do documento original;
    • o cliente [Vue.js] correspondente, com as mesmas funcionalidades, uma tela de login, uma interface Bootstrap adaptada ao papel do usuário logado e a possibilidade de alternar a interface entre francês e inglês ([vue-i18n]).

    Duas funcionalidades do documento original ficam, nesta etapa, fora deste documento: o modo “debug” do cliente original (exibição do template bruto da view atual), que foi deliberadamente omitido desta portagem (veja o Capítulo 6 para os motivos dessa decisão), e a configuração de um atraso de rede artificial, adiada para uma etapa posterior.

    1.2. A quem se destina este documento

    Este documento não pressupõe nenhum conhecimento prévio de [NestJS] nem de [Vue.js]. Cada novo conceito (decorador, injeção de dependência, componente, signal etc.) é explicado quando aparece, com o máximo de detalhes possível — inclusive para leitores que nunca escreveram uma única linha de TypeScript.

    No entanto, alguns conhecimentos básicos ajudam a tirar o máximo proveito deste documento:

    • noções básicas da linguagem JavaScript (variáveis, funções, arrays, objetos);
    • noções básicas de trocas de dados HTTP em uma aplicação web (métodos GET/POST, formato JSON);
    • as tags mais comuns da linguagem HTML;
    • uso da linha de comando (cd, npm install…).

    Não é necessário conhecer previamente a linguagem TypeScript (usada tanto no servidor quanto no cliente): ela é um superconjunto do JavaScript que acrescenta um sistema de tipos, explicado ao longo do documento sempre que é utilizado. O leitor interessado pode consultar o documento [Introduction to the TypeScript Language and the NestJS Framework (2026)], que explica o TypeScript em detalhes.

    1.3. A arquitetura da aplicação

    A arquitetura geral da aplicação não mudou desde o documento original:

    • um servidor web entrega uma única página HTML/CSS/JS, contendo uma aplicação [Vue.js] construída sobre o modelo de componentes (view + lógica associada), que se apoia em serviços para se comunicar com o servidor;
    • o usuário interage com as views exibidas no navegador. As ações do usuário às vezes exigem uma requisição ao servidor [NestJS], que processa a requisição e devolve uma resposta JSON (JavaScript Object Notation); essa resposta é usada para atualizar a view apresentada ao usuário.

    A aplicação em estudo terá a seguinte arquitetura:

    • Em [1], o usuário da aplicação [Vue.js] consulta as camadas [presentation] e [2] dessa aplicação;
    • para executar a ação solicitada pelo usuário, as camadas [presentation] e [2] podem consultar as camadas [Services] e [3];
    • Para prestar o serviço solicitado, a camada [3] pode precisar consultar o servidor JSON remoto — implementado pelo [NestJS] — por meio de [4];
    • Dependendo da requisição recebida em [5], as camadas [6-8] podem ser consultadas;
    • a resposta do servidor percorre as camadas [2-8] na ordem inversa;
    • A view exibida ao usuário, [1], reflete essa resposta;

    Nota: Se a arquitetura do projeto estiver confusa, volte a este diagrama. Observe que o SGBD é tratado pelo servidor, não pelo cliente.

    1.4. Ferramentas utilizadas

    Este documento utiliza as seguintes ferramentas (sua instalação é detalhada no Capítulo 2):

    • Node.js (versão 22 ou posterior) e seu gerenciador de pacotes npm — o equivalente, no ecossistema JavaScript, do que Java + Maven eram para o servidor Spring original;
    • Visual Studio Code, um editor de código gratuito, com suas extensões para TypeScript — o equivalente ao Spring Tool Suite (STS) e ao WebStorm usados no documento original;
    • CLI do [NestJS] ([@nestjs/cli]), uma ferramenta de linha de comando que gera a estrutura do projeto do servidor e inicia seu servidor de desenvolvimento; no lado do cliente, o [Vite] não requer nenhuma instalação global — pode ser usado diretamente via npm no projeto fornecido com este documento;
    • [MySQL] 8 para o banco de dados (o documento original usava o [MySQL] 5 — o próprio esquema relacional permanece inalterado);
    • Postman (ou qualquer outro cliente HTTP), para testar as URLs do servidor que respondem a requisições POST (/addAppointment, /deleteAppointment) — um navegador só consegue testar requisições GET.

    1.5. Funcionalidades da aplicação

    As funcionalidades “de negócio” da aplicação [RdvMedecins] permanecem inalteradas em relação ao documento original; o controle de acesso, porém, é um pouco mais robusto que o original (veja a tabela abaixo):

    • Uma clínica médica emprega vários médicos, cada um com seus próprios horários de consulta;
    • o usuário deve fazer login (nome de usuário/senha) para acessar a aplicação;
    • Uma vez logado, o usuário pode escolher um médico e um dia e ver a agenda do médico nesse dia: cada horário aparece como livre ou reservado;
    • um usuário com o papel ADMIN também pode reservar um horário livre para um paciente de sua escolha e cancelar uma consulta existente;
    • Um usuário com o papel USER pode consultar as agendas, mas não pode reservar nem cancelar (acesso somente leitura) — uma diferença deliberada em relação ao documento original, no qual o papel USER servia apenas para ilustrar uma negação de acesso e não podia ver nada (veja o Capítulo 3, seção “Autenticação”, para as razões dessa escolha).

    1.7. Organização deste documento

    1. Configuração do ambiente de desenvolvimento — instalação das ferramentas, criação do banco de dados e primeira inicialização do servidor e do cliente.
    1. Introdução ao [NestJS] — os fundamentos do framework (módulos, controllers, providers), com um miniprojeto para começar.
    2. O servidor [NestJS] da aplicação [RdvMedecins] — o banco de dados, as entidades [TypeORM], a camada DAO, a camada de negócio, a camada web e a autenticação por token JWT e papéis.
    3. Introdução ao [Vue.js] — os fundamentos do framework (componentes de arquivo único, ref/reactive, composables, provide/inject), com uma revisão de conceitos já vistos no [Angular].
    4. O cliente [Vue.js] da aplicação [RdvMedecins] — a arquitetura do cliente, cada um de seus componentes (inclusive a tela de login), a interface Bootstrap, a alternância entre francês e inglês na interface e um passo a passo da aplicação completa.
    5. Conclusão e próximos passos.
